# Mino Chapter Roadmap

This tutorial builds a terminal agent from scratch in Go using the OpenAI Responses API. The official OpenAI Go SDK handles API communication; Mino implements the interaction flow and the Agent loop introduced in Chapter 03. Each chapter follows one interaction: what the model receives, what the program does with the response, and how control or context reaches the next step. [Getting started](./getting-started.md) covers installation and API settings.

All nine chapters are released, with code, bilingual lessons, and verification. The final chapter, Chapter 09, is available in **chapter-09**, application version **0.9.0**, released **2026-10-12**.

Basic protections arrive alongside the capabilities that need them: Chapter 07 confines file access by construction, and Chapter 08 approves each external tool call and keeps service credentials away from the model. Chapter 09 consolidates existing controls rather than adding the first ones. Prompts and injection detection can reduce risk, but the program and execution environment must enforce actual permissions. Checking only command keywords such as `rm` is not a sufficient policy, and a general Bash tool cannot be confined by path rules alone; that contrast is why structured file tools come before guardrails.

## Chapter 05 implementation boundary

Chapter 05 combines the former manual and automatic compaction chapters. The [lesson](./chapters/05-context-compaction.md) explains the shared interaction and its mock request checks; [setup](./getting-started.md#configure-the-context-window) covers `context_window`, whose omitted or zero value uses **128,000 tokens** without model-metadata discovery.

The local estimate uses serialized UTF-8 bytes plus framing, reserves output space, and triggers above 80% of the input budget. It is not an exact tokenizer. Compaction is limited to one tool-free summary request per attempt and one automatic attempt per user turn. Oversized material, failed or non-shrinking summaries, and context still above the hard budget produce errors; there is no recursive or batched compaction. Original records stay on disk, so compaction is not storage cleanup. Live model quality and provider compatibility remain outside the mock tests' evidence.
