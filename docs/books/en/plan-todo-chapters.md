# Mino Chapter Roadmap

This tutorial builds a terminal agent from scratch in Go using the OpenAI Responses API. The official OpenAI Go SDK handles API communication; Mino implements the interaction flow and the Agent loop introduced in Chapter 03. Each chapter follows one interaction: what the model receives, what the program does with the response, and how control or context reaches the next step. [Getting started](./getting-started.md) covers installation and API settings.

This version of the book covers the chapters up to Chapter 06, released as **chapter-06** (application version **0.6.0**) on **2026-10-21**. Each later chapter is published as its own chapter release. The ten-chapter plan replaced an earlier nine-chapter numbering on 2026-10-21; see [republished releases](./releases.md#republished-releases).

Approvals stay bound to the single inspected call, and injected text, summaries, or tool output cannot grant permission. There is no OS sandbox; the lesson explains why Bash and MCP processes remain outside path rules. Verify with injection, symbolic-link, and policy cases using mock services. Release `chapter-10` (version `0.10.0`). |

Basic protections arrive alongside the capabilities that need them: Chapter 03 approves each Bash command, Chapter 04 refuses to treat an unknown result as success, Chapter 08 confines file access by construction, and Chapter 09 approves each external tool call and keeps service credentials away from the model. Chapter 10 consolidates existing controls rather than adding the first ones. Prompts and injection detection can reduce risk, but the program and execution environment must enforce actual permissions. Checking only command keywords such as `rm` is not a sufficient policy, and a general Bash tool cannot be confined by path rules alone; that contrast is why structured file tools come before guardrails.
