# Mino 章节规划与完成状态

本教程使用 Go 和 OpenAI Responses API，从零实现一个终端 Agent。OpenAI 官方 Go SDK 负责 API 通信，Mino 实现交互流程，以及第 03 章引入的 Agent 循环。每章追踪一次交互：模型收到什么，程序怎样处理响应，控制或上下文如何进入下一步。[准备与安装](./getting-started.md)集中说明安装和 API 设置。

第 01–11 章均已发布，具备代码、双语说明和验证。最新发布的第 11 章随 **chapter-11** 发布，程序版本为 **0.11.0**，发布于 **2026-10-26**。第 12 章正在开发中：代码和章节已经写成，发布标签 `chapter-12`（版本 `0.12.0`）正在准备。第 13–15 章处于规划中：下表描述它们的预期范围，发布前仍可能调整。十章的规划于 2026-10-21 取代了此前的九章编号，`chapter-10` 于 2026-10-26 以权限模式重新发布，见[重新发布的版本](./releases.md#重新发布的版本)。

基础保护随相应能力一起引入：第 03 章逐条批准 Bash 命令，第 04 章拒绝把结果未知的操作当作成功，第 08 章通过构造限定文件访问范围，第 09 章逐次批准外部工具调用，并让服务凭证远离模型。第 10 章统一已有控制，而不是补上第一批控制；第 11 章则让这些控制对模型的效果可以衡量：同样的用例经过同一个循环和同一个决定，SOUL 或工具描述的一处改动靠重复运行来检查，而不是凭一次印象。提示词和注入检测只能降低风险，实际权限必须由程序与执行环境约束；不能只凭 `rm` 等命令关键词判断安全性，通用 Bash 也无法仅靠路径规则限定。正因为这种对照，结构化文件工具安排在安全防护之前。
