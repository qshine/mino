# 准备与安装

这一页负责准备好 Mino。第一章追踪一条问题从终端输入到模型回答的路径，第二章加入历史保存与重启恢复。最新已发布的应用仍是 `v0.1.0`；第二章的目标版本是 `v0.2.0`，目前需要使用包含其尚未发布（Unreleased）实现的开发版源码。

## 准备一台 Mac

支持 macOS 13 及以上，提供 Apple Silicon 和 Intel 两种安装包。安装器会自动选择对应的版本，不需要你先安装 Go。

仓库和发布包现已公开。安装使用 macOS 自带的 `curl`，不需要 GitHub CLI，也不需要登录 GitHub。首次启动配置模型服务时，才需要填写模型 API Key。

## 一行安装

在 Bash 或 zsh 中运行：

```bash
mino_installer="$(curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/qshine/mino/main/install.sh)" && bash -c "$mino_installer" && export PATH="$HOME/.mino/bin:$PATH"
```

此命令使用 **`main` 上尚未随应用发布的安装器（Unreleased）**，下载最新已发布的应用，目前是重新发布的 `v0.1.0` 流式版本。安装器先确定一个版本标签，再通过 HTTPS 下载该版本的 macOS 安装包和校验文件。

安装器校验下载包的 SHA-256 和程序版本后，才替换 `~/.mino/bin/mino`，并设置终端的查找路径。首次安装会创建 `~/.mino`，配置文件会在首次启动填写完成后创建。

## 第一次启动

在任意目录运行：

```bash
mino
```

程序只询问缺失的配置项，所有界面提示均为英文：

```text
API URL [https://api.openai.com/v1]:
Model:
API Key (input hidden):
```

API 地址可以直接回车使用 OpenAI 官方地址。**模型没有默认值**，需要填写服务支持且账号有权限使用的模型名；密钥也需要填写，输入时不显示字符。

自定义服务必须支持 Responses API 流式输出：接受 `stream: true` 请求并返回 `text/event-stream`。Mino 会拒绝仅返回完整 JSON 的端点。填写 API 前缀，例如 `https://gateway.example.com/v1`，不要加上 `/responses` 或 `/chat/completions`。远程地址必须使用 HTTPS。

第二章还会发送有序的 `input` 列表，并请求 `reasoning.encrypted_content`。兼容服务需要接受这些请求字段，以及它返回后又被程序重放的响应项。如果服务在成功完成时没有提供输出项，Mino 会用已完成的流式文本保存回答。

设置保存在 `~/.mino/config.json`。之后配置齐全就直接进入聊天；升级不会覆盖这些设置。密钥以明文保存在本地，目录和文件分别使用 `0700`、`0600` 权限。

修改服务、模型或密钥时，编辑这个文件后重启。空字段会重新询问；设置过程中按 Ctrl+C，已有配置保持不变。Mino 不读取项目内配置、`.env` 或 `OPENAI_*` 环境变量。不要把配置文件放进仓库。

在 `You>` 后输入问题即可。真实问答会请求你配置的服务，并按该服务的规则计费。只输入 `/exit` 可以验证程序能够启动，无需调用模型。

## 查看版本和更新

```bash
mino version
```

无需登录 GitHub 即可更新：重新运行上面的安装命令，获取最新发布版。下载或校验失败时，保留现有程序；安装也会保留模型配置和自定义 `~/.mino/SOUL.md`。

已发布的 `v0.1.0` 仍内嵌旧版更新器，它的 `mino update` 命令需要 GitHub CLI 和 GitHub 登录。公开下载的更新器目前属于 Unreleased，将在后续应用版本中提供。两者的区别见[公开下载与内嵌更新器](./releases.md#公开下载与内嵌更新器)。

早期构建也显示 `0.1.0`，但会等待完整回答。如果使用过这类构建，请重新运行安装命令获取流式输出，**即使 `mino version` 已显示 `0.1.0`，也需要更新**。[第一章基线重置说明](./releases.md#第一章基线重置)记录了这次由所有者授权的替换。

## Mino 的身份

配置齐全后，Mino 在进入聊天前读取一次 `~/.mino/SOUL.md`。文件缺失时，程序用内嵌的默认身份创建它。已有内容会在重启和更新时保留；配置未完成或被取消时不会创建这个文件。

默认内容把 Mino 描述为终端助手，可以帮助回答问题、解释概念、写作，以及讨论用户提供的代码，并要求模型使用你的语言、如实说明限制。修改用户文件可以调整这些指引，重启 Mino 后生效；程序不支持即时重载。完整文本会通过 `instructions` 发送给配置的模型服务，不要在其中放置密钥。

第二章的默认身份说明 Mino 会从本地历史提供已完成的问答。已有的第一章身份仍会保留，其中“每个问题相互独立”的描述也不会自动改变。升级时，请在用户 `SOUL.md` 中把这句过时说明改成符合当前历史功能的描述，再重启程序；Mino 不会为更新这条指引而覆盖你的身份文件。

文件必须是普通文件，包含非空的 UTF-8 文本，大小不超过 64 KiB。目录、符号链接或无效文本会在发送模型请求前被拒绝。目录和文件权限分别为 `0700`、`0600`。Mino 忽略工作目录中的 `AGENTS.md` 和 `SOUL.md`：仓库的 `AGENTS.md` 用于开发，根目录的 `SOUL.md` 仅提供构建时嵌入的默认内容。

## 第二章的本地历史

加载配置和身份后，第二章开发版会打开 `~/.mino/history.jsonl`，恢复已完成的问答。这个文件代表一段对话，记录通过 `turn_id` 关联每轮的输入、回答和结束状态。首次启动的历史文件为空。Mino 还会打开固定的 `~/.mino/history.lock`，确保同一份历史同时只能由一个进程使用。如果启动时提示历史正在使用，请关闭另一个 Mino 进程；退出后锁文件可以继续存在，不应通过删除它绕过仍在运行的进程。

两个文件均使用 `0600` 权限，所在的用户目录使用 `0700`。Mino 拒绝符号链接和非普通的历史或锁文件。对话文本以明文保存在本地；程序不会把配置密钥或原始 API 错误复制进历史。你提交的文本会被保存，其中也可能包含你主动输入的敏感数据。不要把历史及恢复副本放进 Git、截图或共享日志。

只有已完成的问答会随后续问题发送。修改配置中的模型或服务不会新建历史：后续请求会把这些已完成的问答发送给新配置的服务。`store: false` 关闭的是服务端响应对象存储，不会关闭本地文件，也不会阻止上下文传输。

如果启动时修复了不完整或 JSON 语法损坏的最后一行，程序会报告位于 `~/.mino/` 的 `history-recovery-*.jsonl` 备份；它在修复前保存，权限为 `0600`。尚未结束的一轮会被标记为中断，不会自动重试。中间记录损坏、未知字段或版本，以及错误的记录顺序都会阻止启动，历史内容保持不变；应使用已确认有效的备份恢复，不要随意删除记录。

历史限制为每条记录 16 MiB、整个文件 64 MiB。这是文件限制，不是模型的上下文预算。触及限制时，Mino 会报错，不会悄悄丢弃旧记录。如果需要手动重新开始，请先关闭 Mino，保留私有备份，再把 `history.jsonl` 移到其他位置后重启。`/new`、`/clear` 和上下文压缩尚未实现。

早期尚未发布的开发版曾在每条记录中写入 `session_id`。当前格式会拒绝这个未知字段，文件内容保持不变，Mino 不会自动迁移。若要保留这份历史，请先退出 Mino 并制作私有备份，再只移除每行 JSON 对象顶层的 `session_id` 字段。保留 `v`、`seq`、`turn_id`、其他所有字段和值、记录顺序，以及每行末尾的换行符，最后一行也不能遗漏。不要删除消息正文或嵌套数据中的同名内容。也可以备份后移开旧文件，开始一段新对话。

## 从源码学习

若要运行或修改源码，需要 Go 1.27.1 或更高的兼容工具链。克隆仓库后，从仓库目录运行。学习第二章前，请先确认当前源码包含其尚未发布的实现；`v0.1.0` 发布版不包含它。

```bash
git clone https://github.com/qshine/mino.git
cd mino
go run ./cmd/mino
```

`cmd/mino/main.go` 是可执行程序的启动入口。应用代码及对应测试放在 `internal/` 下的 `mino` 包中，由 `app.go` 将启动流程接到终端循环。阅读时从 `app.go` 开始，再沿 `terminal.go` 进入 `responses.go`。

入口以 `mino` 为别名导入 `github.com/qshine/mino/internal`，因此调用仍是 `mino.Main(version)`。

根目录的 `assets.go` 嵌入 `install.sh` 和默认 `SOUL.md`。`internal/cli.go` 使用 `assets.InstallerScript` 执行更新，`internal/soul.go` 使用 `assets.DefaultSoul` 初始化用户身份；两者都不依赖源码目录。

模块文件仍在仓库根目录。`go.mod` 将官方 `github.com/openai/openai-go/v3` SDK 固定为 v3.66.0，`go.sum` 记录依赖校验值。首次构建时，Go 会下载依赖，无需单独安装 SDK。

安装包和源码运行共用用户目录中的配置，第二章源码运行也会使用用户目录中的历史。自动化测试使用临时目录和模拟模型服务，不改动真实历史，也不需要真实 API Key：

```bash
bash scripts/check.sh
```
