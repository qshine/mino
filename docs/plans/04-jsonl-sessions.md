# 第 04 章：JSONL 多会话

状态：**待二次讨论，尚未实现**。目标版本：`chapter-04`。前置：[历史存储](./02-jsonl-history.md)与[工具循环](./03-tools-and-bash.md)。公共约定见[计划索引](./README.md)。

## 1. 本章交付

把一份连续历史扩展成互相隔离的多份会话。用户在会话 A 记住 `pine`，用 `/new` 新建 B；B 的请求没有 A 的内容。用户选择 A 后能继续原来的对话，工具调用和结果也保留。

保持 JSONL，不引入 SQLite、全文搜索、自动标题生成、分支或跨机器同步。会话标识用于定位历史，不让它充当任意文件路径。

## 2. 文件与状态

建议布局：

```text
~/.mino/
  sessions/
    <session_id>.jsonl
  active-session.json
  sessions.lock
  history-migration.json   # 迁移期间持久化目标 ID
  history.jsonl            # 升级迁移后保留的旧记录
```

- ID 使用随机生成的 32 位小写十六进制字符串；用户只能选择枚举中已存在的完整 ID，拒绝 `/`、`..`、路径或模糊前缀。
- 会话 ID 由 JSONL 文件名承载，日志记录不重复保存 `session_id`；每个会话拥有独立的 `seq` 和回合集合。
- `active-session.json` 只保存格式版本与当前 ID，不存密钥或整份历史；采用同目录临时文件、同步、重命名和目录同步更新。
- `sessions/` 为 `0700`，日志、活动指针和锁文件为 `0600`，拒绝符号链接和非预期文件类型。
- 初版使用整个会话库的单进程排他锁，持有到退出。先保证所有创建、切换、清空和迁移不会互相竞态；暂不支持多个 Mino 进程同时操作不同会话。
- 列表从目录和各日志的轻量元数据生成，显示 ID、更新时间、是否当前会话。暂不保存第二套索引，也不自动把私人首句用作标题。

## 3. 命令与运行语义

这些是建议的新命令，不是当前 CLI 已有功能。

| 操作 | 建议行为 |
| --- | --- |
| 无会话时启动 | 创建空会话并设置为活动会话，再显示输入提示 |
| 已有活动会话时启动 | 恢复该会话，执行第 03 章中断检查；不自动调用模型或工具 |
| `/sessions` | 列出已有 ID；不请求模型，不切换 |
| `/resume <id>` | 校验和加载目标，成功写活动指针后切换；失败保持原会话 |
| `/new` | 创建并同步新文件，更新指针后切换；旧会话保留 |
| `/clear` | 展示当前 ID 并确认，清空当前历史与摘要；保留会话 ID、配置、SOUL 和其他会话 |

命令仅在用户输入位置识别，模型输出和工具输出中的同名文本不会执行。生成/执行期间不允许切换或清空；终端目前串行处理，保持这个简单约束。

每次请求从当前会话控制器取得上下文，禁止使用上一个会话的共享消息切片。程序启动时加载的身份不因切换而重新读取。Bash cwd 仍由本次程序启动位置决定，恢复会话不自动切换到历史记录中的目录；每次授权显示实际 cwd。

活动指针损坏或指向不存在的文件时报告错误，提示列出会话并选择有效 ID，不静默用空对话替换原内容。允许进入只处理会话选择命令的恢复状态。

## 4. 从单历史迁移

在没有活动会话的首次升级启动中，持会话库锁，并取得第 02 章旧历史的排他锁，再检查 `history.jsonl`。旧进程仍在使用历史时停止迁移，避免复制期间旧文件继续变化：

1. 使用第 02、03 章的验证和恢复规则读取旧记录；无法安全读取时停止迁移。
2. 生成新会话 ID，并在复制前将目标 ID 写入私有迁移进度文件，采用临时文件、同步、原子替换和目录同步。重试沿用该目标，避免重复导入；空文件按新会话处理。
3. 写入私有临时文件，逐字节复制已验证的日志，同步后发布目标文件；不改变已有 `seq`、回合 ID 或 `call_id`。
4. 已存在同名目标时校验内容或确认它已经由该迁移创建，绝不覆盖不同内容。目标已写好但活动指针写失败时，旧文件仍在，重试可继续完成指针更新。
5. 活动指针持久化后才切换到新存储并结束迁移；迁移进度在确认完成后清理。保留旧文件并明确提示它是迁移留档；以后有有效活动指针就不再导入旧日志。

如果确定目标已经存在且包含迁移后新增内容，但活动指针丢失，不自动覆盖或重新导入：进入会话选择恢复状态。迁移留档含旧的私人历史，后续 `/clear` 不会自动删除它，必须告知用户这一点。升级后不支持同时运行旧版本继续写单历史；留档仅供恢复，不与新会话双向同步。

## 5. 清空的原子边界

用户确认后，在相同目录准备空日志并同步，以原子替换发布，再同步目录；提交成功后才重建内存会话。确认被拒绝、写入/同步/替换失败时不宣称清空成功。如果替换后目录同步失败导致持久性未知，停止写入并在重启时重新检查，不能继续沿用旧内存。

第 05 章把摘要检查点保存在同一 JSONL 中，因此替换空文件也会删除摘要。日志序号可从头开始；持有的旧消息、摘要索引和回合状态必须一起失效。清空不创建可自动恢复的备份，避免出现“已清空”却仍被程序重新加载的情况。

`/clear` 清除活动会话在 Mino 中使用的记录，不承诺磁盘安全擦除，也不撤销 Bash 或 MCP 已经产生的外部效果。旧迁移留档、人工备份和损坏恢复副本不在其删除范围。

## 6. 任务顺序与验收

| 任务 | 依赖 | 建议文件 | 验收与验证 |

| 04-B：列表、新建和切换 | A | `session.go`、`session_test.go`、`terminal.go`、`terminal_test.go` | A/B 两份模拟请求完全隔离；切回 A 后调用结果仍配对；切换失败保持原会话 |

检查点：A–B 演示 A → B → A；C–D 使用含工具记录的旧日志做迁移和清空。运行 `go test ./...`、`bash scripts/check.sh`，文档更新后执行 `npm run book:build`。

## 7. 教程与后续接口

教程聚焦同一句追问在 A/B 中具有不同上下文，并展示原始 JSONL 与请求内容。安装指南补充位置、恢复、迁移留档和清空语义。第 05 章只需在当前会话内追加摘要检查点，不更换存储系统。

## 8. 二次讨论的问题

- 是否接受启动默认恢复上次会话？建议接受，并显示当前 ID。
- 命令采用 `/sessions` 和 `/resume <id>` 是否合适，是否确实需要同时引入启动参数？建议本章先不加启动参数。
- 是否需要人类可读标题？建议先用 ID 和更新时间，避免列表泄露首句和增加索引维护。
- `/clear` 确认采用普通确认还是要求输入 ID？建议输入当前 ID，降低误删概率。
- 初版是否允许整个会话库只能有一个写入进程？建议接受，避免本章同时教授多锁协调。
