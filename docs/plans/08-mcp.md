# 第 08 章：MCP 外部工具

状态：**待二次讨论，尚未实现**。目标版本：`v0.8.0`。前置：[工具循环](./03-tools-and-bash.md)、[预算](./06-context-budget.md)以及第 07 章形成的工具路由。公共约定见[计划索引](./README.md)。

## 1. 本章交付

连接一个用户配置的 MCP 服务，读取其工具描述和 JSON Schema，转换成 Responses 工具；模型发起调用后，Mino 路由到对应服务并回传结果。现有授权、日志、预算与最大循环次数继续适用。

建议初版只支持 **stdio**，使用固定的本地示例服务返回样例数据，不需要真实账户。暂不加入远程 HTTP、OAuth、MCP resources/prompts 自动注入、服务市场或自动安装。采用官方 Go MCP SDK，实施时核对协议支持和固定依赖版本，草案不提前编造 SDK API。

## 2. 配置与连接生命周期

建议使用独立的 `~/.mino/mcp.json`（`0600`），避免把 MCP 可选项混进首次 API 设置交互。每个服务配置包括本地唯一别名、可执行文件绝对路径、参数数组、绝对 cwd 和允许传入的环境变量名称；认证值不写入示例，不插值为 shell 命令。

配置只来自用户 HOME；不自动读取仓库内的服务配置。加载配置、展示实际启动命令和目录并取得确认后，直接启动进程，禁止为了执行数组而再套一层 shell。启动一个服务进程本身可能有副作用，不能等第一次工具调用才考虑这点。

```text
Validate configuration → Approve launch → Start child → Initialize
  → List tools → Publish routing snapshot → Call tools → Close child
```

建议启动/初始化/发现各阶段最多 10 秒，单次调用默认 30 秒，结果上限与已有工具一致为 64 KiB。发现处理分页，设置总工具数和页数上限，检测不前进的游标。候选上限为 128 个工具、16 页；达到限制时该服务不注册工具并明确报错，不悄悄缺一半。

一个服务连接失败时保留聊天和其他服务，但清楚显示其不可用状态。stdout 专用于协议；stderr 按有界、净化后的诊断处理，不能原样泄露环境变量或私有数据。退出时取消挂起调用、关闭连接、终止并回收子进程；继承 Bash 进程清理的限制说明。

## 3. 工具发现与协议适配

建立不可变路由表，每项保存本地暴露名、服务别名、原工具名、schema 摘要、实际服务连接和来源信息。模型只看到经过注册的名称；执行时必须用路由表定位，不从字符串临时拼接目标。

建议暴露名为 `mcp_<server>_<tool>`，使用确定的转义/摘要后缀处理不合法字符、长度和归一化碰撞。不要仅把所有标点替换成下划线后假定不会重名。与本地 `bash`、`read_skill` 一起检查全局唯一性。

- 保留工具参数语义，发现阶段检查 schema 是否能表达为当前 Responses 工具。遇到不支持的引用或结构时拒绝注册该工具并说明原因，不悄悄放宽为任意对象。
- 是否使用 Responses 严格 schema 模式按实际支持确定；MCP schema 不符合严格模式时，不能靠随意添加 `required` 等字段改变服务语义。
- 工具描述、schema 内描述和 annotations 都来自外部服务。`readOnlyHint` 等提示不能直接转化成自动批准规则。
- 初版固定每次连接的工具快照；不在一次用户回合中动态替换 schema。发现服务声明列表变化时，将快照标为过期，在安全边界重新发现或提示重启；默认行为在实施前确认。
- 整份注册工具定义进入上下文预算。过大时提示减少启用服务，而不是未经说明随意隐藏工具。

## 4. 调用、结果和不确定性

模型调用先经过同一个程序授权入口：显示服务、原始工具名、已校验参数和超时；默认逐次确认，不能因为工具名字像读取就自动信任。

`tool_start` 增加服务别名、原工具名和 schema 摘要，记录本次实际路由；日志不保存连接令牌或可复用授权。随后调用 SDK，把结果转成有界的 `function_call_output`，保留模型 `call_id`。

| MCP 返回/故障 | 映射到 Mino 的行为 |
| --- | --- |
| 文本内容块 | 保留块顺序、来源和文本，作为工具数据 |
| `structuredContent` | 保存并序列化为可回传 JSON，不能只取一个 text 字段而丢失结构 |
| 图片、音频、资源引用等非文本块 | 初版明确标记当前不支持的类型；不伪造内容、不自动打开 URI；有可用文本时可保留文本并说明省略项 |
| 服务结果标记工具错误 | 回传工具层错误给模型，与连接失败区分 |
| 初始化/协议/连接失败 | 服务不可用；不以空结果冒充成功 |
| 超时、取消或断开且调用已发出 | 结果可能未知，不能保证远端已取消；不自动重试，按第 03 章未知结果规则处理 |
| 拒绝批准 | 不向 MCP 发起该工具调用，返回拒绝状态 |

进程异常或连接重建不自动重发旧调用；恢复历史也只回放结果。MCP 服务可能自行执行命令、读文件或联网，Mino 对调用的批准不等于对服务内部实现的完整控制。

结果 64 KiB 是适配后的内容限额，还需要在协议输入层限制单消息字节数，候选 1 MiB，避免 SDK 先把无限大消息读入内存。开章验证 SDK 的传输限额支持；若需包装 reader，应在真实传输测试中验证，不仅截断最终显示字符串。

## 5. 任务顺序与验收

| 任务 | 依赖 | 建议文件 | 验收与验证 |
| --- | --- | --- | --- |
| 08-A：本地服务与 SDK 连通 | 07 | `mcp.go`、`mcp_test.go`、`go.mod`、`go.sum` | 用测试子进程完成初始化、分页发现、关闭；验证 SDK 传输限额和取消，不使用真实账户 |
| 08-B：用户配置与生命周期 | A | `mcp_config.go`、`mcp_config_test.go`、`mcp.go`、`app.go` | 非法 cwd/执行文件/权限被拒；启动拒绝时子进程数为零；单服务失败不阻止普通聊天 |
| 08-C：注册和路由 | B | `tools.go`、`tools_test.go`、`mcp.go`、`mcp_test.go`、`context.go` | 两服务同名、归一化碰撞、坏 schema、过期快照和目录预算；调用准确到达对应服务 |
| 08-D：结果和失败闭环 | C | `mcp.go`、`mcp_test.go`、`agent.go`、`agent_test.go`、`history_test.go` | 结构化结果、工具错误、非文本类型、超时和断开都可区分；请求计数证明无自动重试 |

检查点：A–B 证明服务可控地启动和退出；C–D 通过模型模拟器完成一次 MCP 调用后回答，再在调用发出后断线。运行 `go test ./...`、`bash scripts/check.sh`，更新双语教程和服务配置指南后运行 `npm run book:build`。

## 6. 教程与后续接口

讲清楚 MCP 负责发现和调用协议，Responses 负责模型工具选择，Mino 路由并执行权限检查。复用之前的 Agent 循环图，只增加服务节点。第 09 章把服务来源、schema 摘要和当前参数纳入统一决策，不信任服务自报的安全标签。

## 7. 二次讨论的问题

- 是否先只支持 stdio？建议是，远程认证单独规划，避免一章同时解决协议、网络和账户授权。
- 示例服务使用自带最小 Go 服务还是固定版本的外部服务？建议测试使用自带服务，读者示例也应无凭证可运行。
- 每次进程启动是否都确认？建议初版每次确认；以后若持久化信任，必须绑定具体启动配置并可撤销。
- 非文本结果是否允许返回文本部分加明确省略标记？还是整个调用标为不支持？由示例需要决定。
- 工具列表变化时采用安全边界重建还是重启服务？建议先提示重启，保持路由快照简单。
