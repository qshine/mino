# 第 07 章：按需加载 Skills

状态：**待二次讨论，尚未实现**。目标版本：`v0.7.0`。前置：[工具循环](./03-tools-and-bash.md)与[上下文预算](./06-context-budget.md)。公共约定见[计划索引](./README.md)。

## 1. 本章交付

在程序启动和 `/new` 时，发现项目 `.agents/skills/` 与用户 `~/.agents/skills/` 中的技能。模型先看到名称、描述和路径，只有选择某项技能后才调用工具读取完整 `SKILL.md`。

示例放置一个 `go-test` 技能：元数据说明它指导 Go 测试，正文说明如何选择和解释测试。用户提出测试任务，模型先读取技能，再通过已有 Bash 工具提出实际命令；读取技能不授予 Bash 执行权。

不自动安装技能，不执行安装钩子，不扫描任意父目录，不引入子代理、通用文件浏览器或整目录内容注入。项目 `AGENTS.md` 和 `SOUL.md` 仍不作为 Mino 运行时指令。

## 2. 发现规则与目录快照

项目根默认取本次程序启动 cwd，不自动寻找 Git 根或向上遍历；用户根从 HOME 定位。建议只扫描两个根的直接子目录中的 `SKILL.md`，不递归寻找任意 Markdown 文件。

建议 `skillInfo` 保存 `id`、`name`、`description`、绝对 `path`、`source`、内容摘要和长度。`source` 是 `project` 或 `user`，`id` 是来源与目录名组合生成的稳定标识，不由技能正文指定。

- 元数据使用 `SKILL.md` 开头的 YAML frontmatter，至少要求非空 `name`、`description`。使用一个经过评估的 YAML 解析器处理多行和转义，不手写只支持几行字符串的伪解析器；新增依赖在开章确认。
- 建议名称最长 64 字符、描述最多 1024 字节、完整文件最多 64 KiB，并要求有效 UTF-8。元数据提取可有界读取文件，但不会把正文一起发送给模型。
- 目录和文件不能是符号链接；确认规范路径仍位于选定根内。普通坏文件显示净化后的路径和原因后跳过；没有目录是合法的“没有技能”。
- 建议同名时项目级覆盖用户级，并在启动摘要中提示遮蔽关系。排序固定，保证同一份目录产生同一份模型说明。
- 建议有效目录最多 64 项、序列化元数据最多 32 KiB；超出时明确要求缩小范围，不悄悄只挑前几项。

启动发现后形成不可变快照；`/new` 先准备新快照再创建会话，发现发生致命错误时保留原会话。`/resume` 沿用本次进程的快照；重启在当前 cwd 重新发现，旧会话里的读取结果保留其历史来源，不假装代表当前文件。

## 3. 发给模型的内容

在每次请求的 instructions 中加入一个明确分隔的技能目录区块，列出名称、描述、路径和调用用的 ID，并说明“需要时用 `read_skill` 读取正文”。使用结构化序列化与转义，避免名称、描述中的引号或控制字符破坏分隔。

目录是外部文件提供的元数据，不是用户授权或新的系统安全规则。即使物理上位于 instructions 中，也要明确其数据属性；实际权限仍由程序执行策略控制。第 09 章统一来源标记时保持这个性质。

目录加入第 06 章预算。正常请求不能携带全部技能正文；`read_skill` 的结果作为一次工具结果进入历史和上下文，后续可由普通压缩机制处理。不维护一个能跳过预算的隐藏“已加载技能”提示区。

## 4. 读取工具

建议增加 `read_skill`，只接受一个 `skill_id`，不接受任意路径。返回项包含来源、完整 `SKILL.md` 文本与内容摘要；超过上限时整个读取失败，不能把截断正文说成完整技能。

1. 在当前目录快照中查找 ID，未知 ID 返回错误，不委托 Bash 猜路径。
2. 使用不跟随链接的打开方式并检查文件句柄，验证普通文件、路径归属、大小和身份；父目录也要校验，不能只检查一次路径再无条件打开。校验内容摘要与快照一致；发生变化则拒绝并提示重新发现。
3. 读取成功返回有来源标记的工具结果；读取本身不执行 Markdown 中的命令，不自动打开所引用的外部链接。
4. 复用已有工具调用 ID、日志、错误、预算和超时流程。默认允许读取已发现且未变化的技能文件；这不扩展到技能引用的脚本、附件或任意文件。
5. 同一技能重复请求可复用已验证的内存内容，但每个模型调用仍需得到自己的结果，不能漏掉调用与结果配对。跨进程不需要另建缓存库。

本章只保证完整读取 `SKILL.md`。正文引用其他文件时，模型可提出经过批准的 Bash 操作，但不因此获得无确认读写任意路径的权利。自动读取附件与逐层加载作为后续扩展，不在本章实现。

## 6. 教程与后续接口

教程对比“总是带着所有正文”和“先目录、后读取”的实际请求内容，解释技能只是任务知识，执行仍经过工具。第 08 章在本章形成的小型工具路由上接入 MCP，不另建第二个 Agent 循环。

## 7. 二次讨论的问题

- 项目范围采用启动 cwd 还是向上寻找 Git 根？建议 cwd，行为直接且可预测。
- 同名项目技能覆盖用户技能是否合适？另一选择是始终保留两个带来源的名称。
- 是否接受专用 `read_skill`，以及只允许读取本次快照中的文件？建议接受，避免把任意文件读取带进本章。
- YAML 解析器、64 项目录限制和 64 KiB 文件限制是否适合教学样例？
- 文件改变后仅在 `/new` 或重启刷新是否够用？若需要 `/skills reload`，在讨论后明确增加范围。
