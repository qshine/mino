# 第 06 章：上下文预算与自动压缩

状态：**待二次讨论，尚未实现**。目标版本：`v0.6.0`。前置：[手动压缩](./05-manual-compaction.md)。公共约定见[计划索引](./README.md)。

## 1. 本章交付

在每次模型请求前评估即将发送的内容；接近预算时自动调用已有压缩逻辑，再检查预算。用户能够看到何时压缩、为何停止；无法塞入上下文的输入不会被悄悄截断。

本章不做通用模型能力数据库、精确计费、自动更换模型或自动无限分块摘要。预算只是本地估算，兼容端点仍可能返回上下文超限。

## 2. 配置和估算

建议在用户配置中增加可选 `context` 对象，字段为 `window_tokens`、`reserve_output_tokens`、`trigger_ratio`。已有三个必填配置字段保持不变；没有 `window_tokens` 时不猜模型窗口，自动管理保持关闭，启动时说明可配置，手动 `/compact` 仍可用。

建议公式：

```text
W = configured context window
R = reserved output tokens
S = safety margin, initially ceil(W * 0.10)
B = W - R - S                       # estimated input budget
E = estimate(assembled request)     # excludes transport-only fields
trigger automatic compaction when E >= 0.85 * B
send only when E <= B
```

默认输出预留候选为 4096，触发比例候选为 0.85；二次讨论后再定。配置必须为有限正数，要求 `0 < R < W - S` 和 `0 < trigger_ratio < 1`；小窗口应要求显式提供合适的 R，不能偷偷把输入预算改为负数或零。

`E` 必须来自最终请求组装函数，包含 SOUL、后续 Skill 元数据、工具定义的 schema、摘要、近期消息、当前输入、调用参数和工具结果。JSONL 的序号、结束状态和 API 认证不作为模型内容计数；协议包装则要计入估算余量。

在无法准确识别模型 tokenizer 时，建议先使用 UTF-8 字节数加每条协议项开销的保守估算，并显示 `estimated`。它是可测试的近似值，不宣称是上界或精确 token 数。后续需要专用 tokenizer 时再添加依赖。完整响应提供的 usage 可用于诊断估算偏差，但不把上次使用量当作下次准确输入量。

R 应通过当前服务支持的输出 token 上限参数一起发送；推理模型中该上限可能包括非可见输出，开章时核对 SDK 和目标服务语义。不能只在本地扣除 R，却允许服务输出无限增长。

## 3. 请求前的决策顺序

普通请求和工具结果后的继续请求都必须经过同一个预算入口：

1. 组装候选上下文，算出 E、B 和触发线。先检查不能被压缩的部分：身份、工具定义、当前输入和当前未结束工具回合。
2. 不可压缩部分本身超过 B 时直接停止，指出主要占用项；不为没有可能成功的请求付出摘要调用成本。
3. E 小于触发线时直接发送。接近触发线且存在可压缩旧回合时，执行一次第 05 章压缩，并重新组装和估算。
4. 没有足够旧回合可压缩且 E 仍在 B 内时允许发送；超过 B 时停止。
5. 压缩失败且原 E 仍在 B 内，可显示提示后使用原上下文发送一次；原 E 超过 B 则停止。压缩不会留下半提交摘要。
6. 成功压缩后仍超过 B，停止并给出缩短输入或新建会话等具体选项，不丢弃近期回合来凑预算。

建议每个用户回合最多自动压缩一次。工具循环后续仍可检查预算，但不会连续发起摘要调用；需要再次压缩时停止并提示。一次摘要失败也计入本回合尝试次数，避免失败循环。

摘要请求也必须有自己的输入与输出预算。压缩器收到预算参数，在发送前估算；如果摘要输入本身放不下，本章停止并解释，不递归调用自身压缩。

## 4. 超大内容与恢复

| 内容/故障 | 处理原则 |
| --- | --- |
| 单条用户输入太大 | 不发送、不自动截字；若已写入输入记录，记录本地失败状态，下次不把它当作成功回合 |
| 工具输出过大 | 第 03 章执行器先限制原始字节。仍不适合剩余预算时可生成显式标注的展示摘录，保留首尾和原结果状态；不能截断调用参数或弄丢 `call_id` |
| 工具摘录仍放不下 | 不发送；保留已执行结果，不重跑工具；停止本回合并提示 |
| 工具定义或 Skill 目录太大 | 不默默取消工具或遗漏目录；显示占用问题，要求用户调整配置或范围 |
| 服务实际返回上下文超限 | 清楚报告本地估算不足；不自动重试同一请求，不自动再次执行工具 |
| 没有识别服务错误的可靠结构 | 给出已净化的通用错误，不为判断超限而显示原始响应体 |

工具摘录是在上下文组装层产生的视图，JSONL 保留执行器上限以内的原结果；每次同样输入与预算应生成相同摘录。输出需注明原始保留字节数、摘录字节数和截断标记，模型不能把摘录当成完整结果。调用和结果项数量保持一致。

| 任务 | 依赖 | 建议文件 | 验收与验证 |

## 6. 教程与后续接口

教程用小预算的模拟服务展示“触发前 → 摘要后 → 仍放不下”三种结果，区分 token、字节与磁盘大小。第 07、08 章把目录说明和 MCP 工具 schema 加入同一个请求组装入口，不能绕开预算。

## 7. 二次讨论的问题

- 自动预算是否必须由用户填写模型窗口后启用？建议是，避免为任意 `base_url` 猜测能力。
- 初版选择保守字节估算还是增加 tokenizer 依赖？建议先可解释的估算，并保留充足余量。
- 是否接受触发比例 0.85、安全余量 10%、输出预留 4096，以及每回合最多一次自动压缩？
- 工具摘录采用首尾各半还是只保留前段？建议首尾各半，并明确丢失中段。
- 过大的摘要输入是否值得本章引入分块压缩？建议暂不引入，避免掩盖失败处理和调用成本。
