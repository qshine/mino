# Miniagent 章节规划与完成状态

本教程使用 Go，从零实现一个终端 Agent，仅支持 OpenAI Responses API，支持配置 `base_url`、`api_key` 和 `model`。每章从一个具体问题出发，在上一章基础上增加能力，并提供可运行代码和可观察的演示结果。

第 01 章已完成代码、说明和本地验证，其余章节尚未开始。状态统一使用「未开始」「进行中」「已完成」；章节说明、对应代码和必要验证全部完成后，才能标记为「已完成」。

| 序号 | 完成状态 | 章节名称 | 核心内容介绍 |
| --- | --- | --- | --- |
| 01 | 已完成 | [与模型对话：第一个终端程序](chapters/01-terminal-chat.md) | 使用 Go 1.27.1，在 macOS 终端运行，支持 Apple Silicon 和 Intel Mac。启动时只询问缺失的 API 地址、模型和密钥，提供 OpenAI 官方默认地址，模型名称无默认值、必须填写，隐藏密钥输入，自动创建用户主目录下的 `.mino` 文件夹，将配置保存到 `~/.mino/config.json`；配置齐全时直接进入对话。通过 Responses API 实现终端一问一答；每次请求独立，不保留或存储对话历史；可选读取当前目录的 `AGENTS.md`，作为系统指令传入请求。支持中文问答、英文界面提示、退出和错误提示，理解终端输入、请求构造与响应输出。发布版支持一行安装、版本查看和升级，版本按 `0.章节.补丁` 管理。 |
| 02 | 未开始 | 让对话连续起来：内存中的历史 | 在内存中维护对话条目，每次请求携带前文，实现多轮对话；退出程序后历史丢失。理解模型的上下文来自程序传入的内容，区分单轮问答与连续会话。 |
| 03 | 未开始 | 第一个 Agent 循环：工具调用与 Bash | 通过 `tools` 注册 Bash 工具的名称、描述和参数结构，实现「模型请求工具 → Go 执行 → 结果交回模型 → 继续调用或回答」的循环；保留工具调用与结果的关联，展示执行过程。同步引入执行前确认、超时、输出长度限制和最大循环次数。 |
| 04 | 未开始 | 保存与管理会话：SQLite 与 Session | 用 SQLite 保存会话、对话条目和工具调用记录，支持重启后恢复；通过 `/new` 创建新会话并保留旧会话，通过 `/clear` 清空当前会话历史，以及后续章节引入的摘要。区分持久化记录与实际发送给模型的上下文。 |
| 05 | 未开始 | 手动压缩上下文：`/compact` | 将较早的交互整理为摘要，保留近期完整交互和原始历史记录；摘要涵盖用户目标、约束、已完成事项和待办事项。避免拆散工具调用与结果，压缩失败时保留原上下文，并演示压缩前后的信息保留与丢失。 |
| 06 | 未开始 | 自动管理上下文：预算与压缩触发 | 设置上下文预算，考虑系统指令、工具定义、历史与工具结果的占用，为模型输出预留空间；接近阈值时自动复用压缩流程。处理单次输入或工具结果过大、压缩失败及压缩后仍超限的情况。 |
| 07 | 未开始 | 支持 Skills：按需加载任务知识 | 扫描项目 `.agents/skills/` 与用户 `~/.agents/skills/`；启动和 `/new` 时将技能名称、简介及路径注入系统指令。模型选择技能后，通过工具读取完整 `SKILL.md`，理解技能发现与按需加载，避免一次加载所有正文。 |
| 08 | 未开始 | 支持 MCP：接入外部工具 | 由 Go 程序连接 MCP 服务，发现工具的名称、描述和参数结构，转换为 Responses API 的工具定义；将调用转发给对应服务，再把结果交回模型。复用已有 Agent 循环，处理命名冲突、连接失败和工具错误。 |
| 09 | 未开始 | 护栏 Guardrails：让 Agent 在授权范围内行动 | **上下文护栏**：讲解越狱与提示注入，区分可信指令和文件、工具、MCP 返回的外部内容，避免摘要丢失来源与信任边界。**工具执行护栏**：在程序中检查具体操作与参数，返回允许、拒绝或请求授权；删除等危险操作须获用户授权，授权绑定实际执行内容。**数据访问护栏**：约束文件与数据的读取、写入、删除范围，保护敏感信息，检查路径越界与符号链接；说明通用 Bash 的绕过风险及操作系统权限、沙箱的作用。用注入、拒绝授权和越界访问案例验证护栏。 |

基础保护随相应能力一起引入，第 09 章负责系统梳理并统一权限策略。提示词和注入检测只能降低风险，实际权限必须由程序与执行环境约束；不能只凭 `rm` 等命令关键词判断安全性。
